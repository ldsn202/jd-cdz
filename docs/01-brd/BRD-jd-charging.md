## 1. 项目背景

### 1.1 业务现状

京东充电桩安装业务由京东零售、京东物流和本地安装服务商协作完成。服务商在自己的系统中管理施工、物料与应收，京东侧通过安装管理平台归集资料、核查安装结果并开展业务对账。

现有工作台已经具备工单管理、待办、资料审核和记录追溯能力。不同服务商的资料格式、字段含义和费用拆分方式存在差异，人员仍需花费大量精力理解资料、查找依据、核对差异和反复沟通。

### 1.2 核心问题

| 问题 | 业务影响 |
| --- | --- |
| 不同服务商的信息表达不统一 | 安装资料交接依赖人工解释、整理和重复录入 |
| 安装事实与证明材料分散 | 核查人员需要跨页面、跨文件寻找差异及其依据 |
| 账单项目与计费范围存在差异 | 对账人员需要先完成项目对应，再判断差额是否合理 |
| 工作台主要提供查询与操作入口 | 人员需要主动找问题、组织信息，才能形成处理判断 |

### 1.3 改造机会

AI 已具备理解多样资料、整理信息、查找证据和解释差异的能力。结合现有系统中的工单与业务记录，可以把这些分析工作提前完成，减少人工准备判断的成本。

**工作台 2.0 的改造重点是围绕 AI 能力重新组织业务交互，让人员从逐项查找和操作，转向处理已经形成的分析结果。**

## 2. 项目目标与成功标准

### 2.1 项目目标

提升安装资料交接、安装结果核查和业务对账的处理效率，减少重复录入、资料查找及无效沟通，同时保持业务判断的准确性与责任清晰。

### 2.2 核心设计原则

**业务信息到达后，系统主动完成适用的整理与分析；人员打开工作台，优先看到需要自己核实、确认或处理的事项。**

- 判断型 Skill 的分析结果直接服务于业务处理，日常工作不要求人员逐个选择 Skill、发出指令。
- 分析结果同时提供判断依据，人员重点确认事实、核实证据和处理例外。
- 已确认且适用的规则与信息持续复用，减少重复操作。
- 正式业务决定由原责任人作出，不因引入 AI 增加一轮重复审核。

### 2.3 成功标准

| 维度 | 衡量方式 | 目标方向 |
| --- | --- | --- |
| 处理效率 | 同类业务的人工处理时间与操作次数 | 减少资料准备、跨页查找和重复填写 |
| 协作效率 | 同一事项的补充沟通次数与处理周期 | 减少因信息遗漏、理解不一致造成的往返 |
| 业务质量 | 资料返修、核查遗漏与对账错误情况 | 在提效的同时保持或改善处理质量 |

基线与具体改善幅度由业务实测确定，试运行期间按同类业务进行前后比较。

## 3. 目标用户与核心场景

### 3.1 目标用户

| 用户 | 核心诉求 |
| --- | --- |
| 京东安装业务人员 | 快速掌握安装情况，核实差异及依据，完成资料审核与业务对账 |
| 京东物流履约协同人员 | 掌握影响安装履约的问题，协调服务商处理 |
| 服务商对接与资料人员 | 降低接入、资料整理和跨系统交接的负担 |
| 服务商应收负责人 | 明确账差原因，按职责核实费用并处理原账目 |

### 3.2 核心业务需求

| 场景 | 工作台需要提供的能力 | 人员保留的工作 |
| --- | --- | --- |
| 服务商接入与配置调整 | 接入配置 Skill 辅助理解服务商资料，形成可复用的对应关系 | 确认业务含义与适用范围 |
| 安装资料交接 | 安装资料整理 Skill 将分散材料整理为可核实的安装信息 | 确认安装事实，补充缺失信息并提交 |
| 安装结果核查 | 安装资料核查 Skill 围绕安装差异查找相关证据，形成核查参考 | 判断依据是否充分，作出审核决定 |
| 业务对账 | 对账差异解释 Skill 帮助理解费用差异及其依据 | 核实费用合理性，按原职责处理差异 |

### 3.3 相比老工作台的交互变化

| 工作环节 | 老工作台 | 工作台 2.0 |
| --- | --- | --- |
| 开始处理 | 人员进入待办后，自行查找资料、组织信息 | 事项中直接提供已完成的分析结果与待处理问题 |
| 整理资料 | 人员阅读不同材料，再整理填写 | 系统准备整理结果，人员确认和补充 |
| 核查差异 | 人员对照内容，再寻找支持依据 | 系统呈现差异与相关证据，人员核实并决定 |
| 核对账单 | 人员对应项目、计算差额、查找原因 | 系统完成适用的对应与分析，人员聚焦需要核实的费用 |
| 跟进补充 | 人员重新串联补充内容与原问题 | 系统接续原事项，更新分析结果供人员继续处理 |

**人员的主要工作转为核实、确认和处理例外；找资料、做整理及重复核对由系统更多承担。**

## 4. 项目范围

### 4.1 本期范围

- 改造京东侧工作台的业务处理方式，围绕需要人员处理的事项组织信息与分析结果。
- 引入接入配置、安装资料整理、安装资料核查和对账差异解释四类能力。
- 支持已确认关系的复用，以及资料补充后的连续处理。
- 保留原有工单查询、资料审核和处理追溯能力，与现有业务系统协作。

### 4.2 范围边界

服务商继续使用自己的业务系统，双方正式记录和账单保持原有归属。工作台负责辅助理解、核查与协作，业务决定和原账目修订仍由相应责任人执行。

本期不替换服务商完整业务系统，不重建购买、库存及财务全流程，不由 AI 自动批准费用、修改真实账单或执行付款。设备控制、故障维修与售后管理不在本期范围内。

## 5. 关键假设与风险

| 假设或风险 | 影响与应对方向 |
| --- | --- |
| 业务资料能按授权取得，且足以支撑分析 | 核实可接入范围；缺失资料仍由原责任人补充 |
| AI 对资料或费用含义理解有误 | 提供可核实的原始依据，保留人工纠正与业务决定 |
| 服务商资料与规则持续变化 | 支持必要的配置调整，避免错误关系持续复用 |
| 新交互增加额外确认或重复操作 | 以各角色完整工作过程评估，确保准备工作减少且不增加重复审核 |
| 缺少可靠的效率与质量基线 | 在试运行前建立同类业务基线，分别评估效率和质量 |
