# 00-02-progress 当前进度

项目的当前进度快照。**进度不用抽象阶段词描述，用流水线产物定位**：每个阶段对应一份具体文件，文件的状态就是阶段的状态。AI 每日启动时读本文件，沿定位表找到第一个非"已完成"的行，就知道现在到哪、下一步读写什么文件。

## 文件命名

```
progress.md        一个项目只维护一份，持续更新
```

## progress.md 固定结构（三章）

### 一、流水线定位表

九个阶段按顺序排列。**第一个状态不是"已完成"的行 = 项目当前位置。** Skill 的运行实测随开发与测试阶段补齐。

| # | 阶段 | 产物文件 | 完成判据 | 状态 |
|---|------|---------|---------|------|
| 1 | BRD | `docs/01-brd/BRD-<slug>.md` | 用户确认终稿 | |
| 2 | 原型 | `docs/02-prototype/page-list.md` | 清单内全部页面状态为"已确认" | |
| 3 | 技术底座 | `docs/03-foundation/` 七类（术语 / 外部接口 / ER / 业务流程 / 表结构 / 本系统接口 / 系统流程） | 七类文档全部定稿 | |
| 4 | 业务 Skills | `docs/04-skills/README.md` 及业务定义 | 输入、判断、输出、失败边界和验收方法明确 | |
| 5 | PRD | `docs/05-prd/mainprd-<slug>.md` | 含独立 mock 数据专题，索引内全部 subprd 状态为"已评审" | |
| 6 | 测试用例 | `docs/06-testcase/tc-main-<slug>.md` | 用例覆盖全部 subprd 的验收标准 | |
| 7 | 开发计划与实现 | `docs/07-delivery-plans/task-kanban-<slug>.md` | 看板全部 Task 状态为"已完成" | |
| 8 | 测试执行 | `docs/08-test-reports/index.md` | 全部 PASS，defects.md 无未关闭项 | |
| 9 | 上线 | `docs/09-deploy/cloud-deploy.md` | 公开地址可访问，配置项全部生效 | |

状态取值只有四种：`未开始` / `进行中` / `待确认` / `已完成（日期）`。

### 二、卡点与风险

阻塞事项：卡在哪个阶段的哪份文件、依赖谁、需要什么支持。没有写"无"。

### 三、最近动作

最近 3-5 条：日期 + 动作 + 产出文件路径。超出 5 条时删最旧的。

## 示例

```markdown
# 项目进度

> 更新时间：2026-08-22

## 一、流水线定位表

| # | 阶段 | 产物文件 | 完成判据 | 状态 |
|---|------|---------|---------|------|
| 1 | BRD | docs/01-brd/BRD-task-app.md | 用户确认终稿 | 已完成（08-20） |
| 2 | 原型 | docs/02-prototype/page-list.md | 全部页面已确认 | 已完成（08-21） |
| 3 | 技术底座 | docs/03-foundation/ 七类 | 七类文档定稿 | 进行中 |
| 4-9 | … | … | … | 未开始 |

## 二、卡点与风险
- 外部推送接口文档未拿到，03-02-external-apis 无法定稿，需 08-23 前确认

## 三、最近动作
- 08-21 原型全部确认 → docs/02-prototype/page-list.md
- 08-20 BRD 终稿确认 → docs/01-brd/BRD-task-app.md
```

上例中第 3 行是第一个非"已完成"行——当前位置就是技术底座，下一步该读写 `docs/03-foundation/` 下的文件。

## 更新纪律

1. 每完成一份产物文件，立刻更新对应行状态。
2. 只允许一个"进行中"；开始新阶段前，先把上一阶段置为"已完成（日期）"或"待确认"。
3. 本表与 `docs/07-delivery-plans/` 的看板口径一致：流水线行管阶段，看板管阶段内的 Task。
