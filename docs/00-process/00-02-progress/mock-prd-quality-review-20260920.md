## 1. 已具备的基础

独立模拟来源、前端只请求业务API、业务逻辑真实执行、真实文件字节、固定种子、100家服务商/1000工单/3账期的开发基线、读写回查、AI mock与real分开、预期答案不进入输入，这些方向均明确。问题集中在生成和验收规则是否可执行，增加规模不能替代这些规则。

本次仅检查文档与既有契约；没有重跑Skill、模型或程序测试，未修改mock PRD的功能定义。上一轮五项跨PRD问题保持已处理，本轮是新增的mock专题评审。

## 2. 优先解决的四项

### 1. 重置缺少本系统归属与在途任务处理定义

位置：mock PRD §6.1—6.2。文档只把模拟来源按datasetId分目录，却要求清理本系统对应导入记录、分析、决定和任务。已读的七域schema未登记datasetId归属字段或数据集清理映射；历史记录还有no_delete保护，普通DELETE不能直接照流程清理。

“停止后台任务”也没有说明如何处置正在运行的CLI、已发出的外部写入、迟到的回执和重启后旧任务。先重建来源、再分步删除本系统状态，若中途失败，可能留下混合代次；独立上传文件的字节保留也不等于其工单、版本与引用仍能使用。

修订要求：明确数据集隔离单位及模拟来源→本系统记录/文件的归属方式；选定独立数据库整体恢复或有维护边界的精确清理方案；规定暂停、在途处理、重置代次、迟到结果拒绝、失败恢复与恢复服务的条件。混合使用实际上传材料时，保护其完整关联链，不能只保留文件。验收覆盖重置中断和旧任务迟到。

依据：[事项schema](../../03-foundation/03-05-schema/work-item-schema.md) §1（固定历史与受控删除）、[证据schema](../../03-foundation/03-05-schema/evidence-schema.md) §4（封存输入不可更改）、[执行schema](../../03-foundation/03-05-schema/execution-schema.md) 状态与恢复。

### 2. cursor持久化表述会导致新变化永远不可见

位置：mock PRD §6.1，“同一cursor重读返回相同内容”。上游规定空批nextCursor=cursor。若把该句实现成永远缓存同一cursor的整批响应，第一次空批之后，新产生的变化就无法通过该cursor读取。

修订要求：稳定的是已存在的changeId及内容；没有新事件且相同边界的重放可重复，空批之后出现新事件必须可读。明确生产者追加变化与消费者提交读取位置的职责；GET不得代替消费者确认推进。消费者须先可靠保存整批变化及后续任务，再条件更新自己的位置。覆盖空批后追加、分页中追加、重复事件、崩溃前后接续及旧代次cursor拒绝。

依据：[来源变化契约](../../03-foundation/03-02-external-apis/source-record-changes-read.md) §3.1、§3.3。

### 3. 生成配置没有确定的分配规则

位置：mock PRD §3.2、§5.1。anomalyRatio给出整体比例，scenarioMix又给各场景比例，却未定义统计单位（服务商/工单/账单/材料）、场景是否可重叠、两个参数冲突时如何处理、整数取整与覆盖保底。格式不同本身也不必然属于异常。

同一输入无法推出唯一应生成多少条各类记录；“至少一次”与“同一形态跨服务商、跨格式”也未形成可检查的覆盖门槛。仅检查总量1000工单不足以证明真实业务差异。

修订要求：按业务对象定义计数单位，区分互斥主场景与可叠加变体；明确数量/比例优先级、非法配置拒绝、确定性分配与覆盖矩阵。每种模板须有真实字段语义/单位/结构差异，不以改文件名或服务商名算覆盖。配置产物需直接列出场景实例与来源对象编号供回放。

### 4. 场景与金额校验含错误归类

位置：mock PRD §5.1、§3.2。

- NOT_SUBMITTED是整理与首次提交前的正常状态，上游明确“不因此标为缺失”；不得单凭该状态制造缺项。
- NOT_PROVIDED、已取得说明但meaning未知、FORMAT_ASSOCIATION不明是不同分支。NOT_PROVIDED时formatDefinition=null，不能要求同条记录还带不存在的字段meaning；须拆为独立场景。
- “证据不足”和“指定版本不可取得”分别是业务缺项和读取失败，不能统一用40901表示。
- 外部接口无权限可返回40301；本系统越权资源深链接按公共契约返回404，不能对所有层的越权一律断言40301。
- 金额复算不能无条件要求数量×单价。固定收费允许数量/单价为空，原amount仍可有效；源总分不一致应作为明确负例保留，验证器既要拦意外错误，也要确认预设负例按预期失败，不能把全部负例拒之门外。

依据：[工单上下文](../../03-foundation/03-02-external-apis/installation-work-order-context.md) §3.3、[格式说明](../../03-foundation/03-02-external-apis/provider-documents-format-read.md) §3、[材料读取](../../03-foundation/03-02-external-apis/source-material-read.md) §4、[公共接口](../../03-foundation/03-06-provided-apis/common-contract.md) 权限规则、[京东账单](../../03-foundation/03-02-external-apis/jd-bill-read.md) §3.2。

## 3. 随后补齐的三项

### 5. 第一类Skill的验收口径仍有旧表述

位置：mock PRD §5，“真实Skill提出映射建议”。已验收Skill明确生成TRANSFORMATION_CONFIG完整执行规则。mock专题须验收原始记录→生成规则→程序试转换→启用→后续同格式新记录自动转换；另外覆盖格式版本变化、未知枚举与缺字段，不把文字建议当作完成。当前Skill本体没有被本轮修改。

依据：[转换Skill](../../04-skills/provider-mapping-config/SKILL.md) §1—3、[规则目录](../../04-skills/provider-mapping-config/references/rule-catalog.md)。

### 6. 验收有证据清单，缺少逐场景可判定结果

位置：mock PRD §3.3、§4、§7。当前要求报告和回查证据，但没有固定场景清单的结构：输入对象和版本、触发动作、预期来源变更、预期系统状态、必须出现的证据及禁止发生的动作。故障启用也未定义命中目标、发生阶段、次数和复位条件，难以稳定复现“源端已写入但响应丢失”。

修订要求：每个场景有独立于模型输入的验收记录，确定性程序输出精确比较；AI按原文支持、关键事实、证据引用、保留缺项及越权动作检查，不能只比自然语言全文。故障控制必须按目标与阶段发生，记录命中日志；同键不同正文、源端成功后重复调用不二次写入等验收应显式列出。无需在PRD写全部实现代码。

### 7. “同种子同文件摘要”的可复现边界未定义

位置：mock PRD §3.1—3.2、§6。文档要求文件摘要相同，但PDF/XLSX等生成过程可能带创建时间、随机内部标识；只固定业务randomSeed并不能保证字节级复现。fixedNow用于初始数据，运行后的提交、版本变化及故障恢复仍需可推进的时钟或确定事件序列。

修订要求：区分初始生成复现、运行事件回放、AI结果波动三类；固定文件元数据与生成依赖/实现版本，明确排序和ID规则及清单摘要算法。初始业务字节可以要求一致，真实模型的自然语言输出不承诺逐字复现。场景时钟应能推进，不能所有操作都永久使用同一fixedNow。

## 4. 当前建议

先修四项优先问题并补三项验收细节，再冻结mock生成器、模拟接口和重置的开发任务。PRD已有结构可保留，无须推倒重写；SQLite还是JSON、具体CLI命令可以留在详细设计，数据归属、生成规则和验收结果不能留到联调时临时决定。
