## 0. 本计划使用指南

**mock提供各外部系统的原始业务事实与可操作的来源状态，本系统负责真实业务处理。** 允许同一进程承载接口；每个来源保留自身记录、权限、版本、失败和修订行为。

```text
显式业务事实 + 多服务商模板 → 各来源原记录与实际文件 → 独立外部HTTP接口
                                                            ↓
人员打开工作台 ← 本系统API ← 实际导入/转换/计算/分析/保存/状态流转
                         人员确认 → 外部写接口 → 保存结果 → 按原编号回查
独立验收预期 ── 仅验收工具读取，不进入业务接口或Skill输入
```

质量要求依次检查：原文可读、语义有差异、跨系统事实有关联、缺项与错误有边界、写入后来源确实改变、重启和恢复仍可回查。大量记录不能代替这些检查。

按主计划→看板→当前子计划读取。本文原始工程盘点保留为 2026-09-20 计划制定时的基线；当前实现与验收状态以上方快照、任务表及 T4.2 的实际证据为准。

## 6. 风险与应对

| 风险/依赖 | 处理方式 | 归属 |
| --- | --- | --- |
| 数量足够但模板只有名字变化 | 校验语义/单位/结构差异，固定样本人工读原文；生成器独立验证 | T1.1—T1.3 |
| 生成器及验收使用同一错误算法 | 固定手算预期和单值破坏检查，验收不导入生成计算逻辑 | T1.3 |
| 契约与mock字段漂移 | 在启动和HTTP测试中对照具体契约；差异先登记再修，前端不补字段 | T0.1、T2.1—T2.6 |
| 所有来源聚合成一个大响应 | 13操作逐项核对，禁用后端直接读来源库及预期文件 | T3.2、T4.1 |
| 对故障只改返回不改实际行为 | 丢响应前真的保存，读取失败真的阻断指定对象/版本，保留写次数 | T3.1 |
| 实际上传及在途任务被恢复操作破坏 | 配对新环境切换、旧结果隔离、实际上传旧环境完整保留 | T3.1、T4.2 |
| 业务服务尚无实现 | 来源可独立验收；业务最终验收依赖另行落实，不临时伪造 | T4.2 |
| 已通过模型场景重复耗费 | 输入/Skill/运行程序一致则引用旧证据；新增联调只验证新增影响 | T3.2、T4.2 |
