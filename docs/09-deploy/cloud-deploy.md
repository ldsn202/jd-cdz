## 1. 部署组成与前置

| 部分 | 目标 | 尚待落实 |
|---|---|---|
| API及静态前端 | Cloudflare Worker + 静态资源 | Cloudflare账号、域名、环境名、身份提供方接入 |
| 业务数据 | D1，绑定DB | 真实database_id、备份与恢复验证 |

| 后台执行 | 支持Node、OpenCode、Python、Poppler、Tesseract的独立计算环境 | 环境及运行账号待确认；普通Worker不能直接执行本机CLI |

现有 `DEV_IDENTITY_TOKENS` 只用于本地开发，真实身份提供方尚未接通。禁止把Vite开发代理、开发token映射和mock控制接口直接公开。T5.1业务闭环与完整权限验证是发布前置。

## 2. 待执行发布步骤

1. 确定上述资源和身份协议，建立独立环境配置。保留本地配置，不替换零占位database_id后直接发布。
2. 根据锁文件安装依赖，执行API类型检查、前端构建、工程回归及逐条正式业务验收，保留报告。
3. 用Cloudflare控制台或Wrangler创建D1、R2，回填环境专属绑定；真实密钥通过secret管理，不写入vars及Git。
4. 导出上线前D1备份，确认恢复方法；在空验证库先执行全部迁移，再按发布窗口执行目标库迁移。历史保护触发器须保留。
5. 完成前端构建后部署Worker；记录部署版本、配置版本、迁移编号及实际地址。
6. 启动独立后台程序，显式配置Worker地址与受控SERVICE凭据；AI real须两端同时启用。检查材料读取、租约心跳、失权拒绝和原操作回查。
7. 运行健康、身份、角色读写、上传原文、未知结果恢复及真实来源闭环验收。通过后开放给目标人员。

Wrangler命令的具体账号、环境、资源名必须在发布时用官方文档和 `wrangler --help` 复核。本任务未创建云资源，也未运行远端迁移或部署。

## 3. 回滚

先停止领取新任务，保留已发出操作及其原编号；外部结果未知时继续按原编号回查，不能重新提交。恢复经过验证的上一Worker版本及对应后台版本，核对数据库兼容性。应用回滚不会自动回滚D1数据；数据恢复必须有已验证备份、明确停写窗口和恢复范围，不能删除历史记录代替回滚。上传R2对象与固定材料版本一并保留。
