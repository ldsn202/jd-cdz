## 三、系统架构与全局设计原则

<!-- 一张 ASCII 架构图：端、服务端、外部系统各自负责什么 -->

```
┌─────────────┐     ┌──────────────────┐     ┌──────────────────┐
│  用户端      │────→│  服务端           │←────│  管理端           │
│  纯渲染层    │     │  规则计算+数据聚合  │     │  配置界面          │
└─────────────┘     └────────┬──────────┘     └──────────────────┘
                             │
                    ┌────────┴────────┐
                    │  外部系统         │
                    ├─ 推送平台        │ → 到期提醒下发
                    └─────────────────┘
```

**核心设计原则**（跨功能块成立，子 PRD 不重复）：

| 原则 | 含义 |
|------|------|
| 前端是纯渲染层 | 拿到什么展示什么，不做业务判断、不硬编码文案 |
| 服务端算好再给 | 聚合数据 + 读配置 → 实时计算 → 返回可直接渲染的 JSON |
| 配置即时生效 | 管理端改配置后，用户下次打开即生效，不发版 |
| 可降级不白屏 | 任一数据源失败不影响主接口返回，展示默认值 |

## 五、页面结构与接口调用全景

### 5.1 页面区域

<!-- 一张 ASCII 图：页面从上到下几个区域，每个区域标注数据源 -->

```
┌─────────────────────────────┐
│ 顶部导航区                    │  ← 固定：返回 / 标题 / 设置
├─────────────────────────────┤
│ A. 到期提醒条（条件展示）       │  ← 数据源：/api/tasks?dueSoon=1
├─────────────────────────────┤
│ B. 任务列表                   │  ← 数据源：/api/tasks
├─────────────────────────────┤
│ C. 新建任务入口                │  ← 纯前端交互，弹新建面板
└─────────────────────────────┘
```

### 5.2 接口调用时序

<!-- 页面初始化调哪几个接口、顺序、并行关系。复杂时序画成图放 03-foundation/03-07-system-flows/，这里链接 -->

页面初始化共调用 2 个接口：先 `/api/tasks?dueSoon=1` 决定 A 区显隐，再 `/api/tasks` 渲染 B 区；两接口可并行。完整链路图见 [sys-task-list](../03-foundation/03-07-system-flows/sys-task-list.md)。

### 5.3 区域联动

<!-- 用户在某个区域操作后，其他区域怎么刷新 -->

用户新建或完成任务后：A 区计数和 B 区列表同时重新加载，先展示骨架屏，数据返回后替换渲染。

## 六、系统数据全景

<!-- 配置 / 数据从哪来、经过哪步处理、到哪端展示。一条链路写清 -->

```
管理员在管理端修改提醒规则
    ↓
调用管理端接口保存，写入配置表
    ↓
用户打开页面，用户端请求 /api/tasks
    ↓
服务端实时读取最新配置 + 任务数据
    ↓
规则计算（到期判定 / 排序 / 文案匹配）
    ↓
返回可直接渲染的 JSON → 用户端直接渲染
```
