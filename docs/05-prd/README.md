> 下游（引用我）：无

PRD 分两层：**主 PRD 只做索引和全局约定，子 PRD 按功能块逐个详述**。功能块的字段级细节只写在对应子 PRD 里，主 PRD 不重复。

## 文件命名

```
mainprd-<slug>.md             主 PRD，索引 + 全局约定，一个项目只有一份，slug 为项目英文短名
NN-subprd-<功能块>.md          子 PRD，一个功能块一份，NN 为两位序号，例：01-subprd-task-list.md、02-subprd-task-notify.md
```

本目录自带两个模板：[`mainprd.md`](mainprd.md)（主 PRD 骨架）、[`subprd.md`](subprd.md)（子 PRD 骨架，复制后按上述规则改名）。

## 两层分工

| 层 | 写什么 | 不写什么 |
|----|--------|---------|
| 主 PRD | 产品定位、用户角色、系统架构、全局设计原则、全局文档导航、页面结构与接口调用全景、各子 PRD 章节速查大纲 | 具体字段、具体交互、具体规则 |
| 子 PRD | 本功能块的需求清单、页面布局、区块详述（用户体验 / 数据链路表 / 异常兜底）、使用字段、接口业务说明、管理台配置、验收标准 | 其他功能块的内容、全局原则 |

## 功能块索引表（主 PRD 的核心章节）

主 PRD 为每个子 PRD 维护一行索引 + 一张内容速查表，读索引就能判断该去哪个文件找细节：

```markdown
| 功能块 | 子 PRD | 状态 | 内容要点 |
|--------|--------|------|---------|
| 任务列表 | [01-subprd-task-list.md](01-subprd-task-list.md) | 已评审 | 列表展示 / 排序规则 / 空态 / 分页 |
| 到期提醒 | [02-subprd-task-notify.md](02-subprd-task-notify.md) | 草稿 | 提醒触发 / 推送文案 / 失败兜底 |
```

**状态**取值：草稿 / 待评审 / 已评审 / 已交付。

## 拆子 PRD 的规则

1. 一个功能块对应一个用户可感知的完整能力（一个页面区块或一条完整流程），不按技术模块拆。
2. 子 PRD 之间不互相引用细节，需要对方信息时回主 PRD 索引确认边界。
3. 业务功能块范围跟 `01-brd/` 的 In Scope 功能点一一对应。用户明确要求的独立 mock 数据 PRD 作为开发验证配套专题登记，不扩充生产业务功能范围。

## 运行数据要求

- 每个业务子 PRD 写清数据取得接口、后端计算、保存位置、处理后回查和失败表现，前端不得自造业务记录与成功结果。
- mock 专题独立覆盖生成、关联校验、多服务商规模、模拟接口读写、版本变化、重置和完整验收；具体标准见该专题 §7。
- 开发计划须安排数据生成与校验、模拟接口、业务接入和闭环验收任务；测试用例分别验证数据质量、接口行为、真实业务流程和 Skill 运行。
- 进入正式评审前补齐 foundation 字段与接口引用；当前专题草稿不能直接作为实现已完成的依据。
