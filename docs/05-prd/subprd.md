## §3 任务列表区

### 3.1 用户体验

**数据来源**：`GET /api/tasks` 返回的任务列表（含 `title` / `deadline` / `status`）

**布局**：

```
┌──────────────────────────────────┐
│ 写周报              今天 18:00     │  ← 临期任务，时间红色
│  ├ 进行中                          │
│ 买牛奶              08-25          │  ← 普通任务
│  ├ 进行中                          │
│ 交社保              已完成         │  ← 已完成沉底，灰色划线
└──────────────────────────────────┘
```

**交互**：
- 点击任务行 → 进入任务详情
- 右滑任务行 → 标记完成 / 删除
- 滚动到底 → 加载下一页

**前端职责**：直接渲染 `title` / `deadline` / `status` 字段，不做排序、不做状态判断；排序和分组由服务端返回顺序决定。

### 3.2 数据链路

> 端到端追踪：UI 元素 ← API 字段 ← 数据源。字段完整定义见接口文档，这里只写本区域用到的。

| UI 元素 | API 字段 | 计算规则 | 数据源 |
|---------|----------|---------|--------|
| 任务标题 | `title` | 直透 | `task.title` |
| 截止时间 | `deadline` | 直透，前端格式化为"今天 HH:mm / MM-DD" | `task.deadline` |
| 状态样式 | `status` | 直透（0 进行中 / 1 已完成） | `task.status` |
| 列表顺序 | 数组顺序 | 服务端排好：进行中按截止时间升序，已完成沉底 | — |
| 临期标红 | `dueSoon` | 服务端计算：截止时间在 24h 内且未完成 | `task.deadline` 与当前时间比较 |

### 3.3 异常与兜底

**服务端兜底**：接口异常时按统一返回壳返回错误码，前端按下表执行渲染兜底。

**前端渲染兜底**：

| 场景 | 处理 |
|------|------|
| `title` 为空 | 标题位显示"未命名任务" |
| `deadline` 为空 | 时间不显示，不标红 |
| 列表为空 | 空态插画 + "暂无任务，点右下角新建" |
| 接口超时/异常 | 错误提示 + 点击重试 |
| 加载更多失败 | 底部 toast"加载失败"，停留在当前页 |
