## 1. 目标与范围

**各外部系统分别通过自己的模拟接口提供业务数据；本系统后端按业务需要调用这些接口，执行真实处理后，将结果返回工作台。**

身份来源中的京东账号统一为 `acc-jd-business`（京东业务账号），具备核查、对账与履约三组已授权动作。首次生成仅提供这个京东业务账号；已有环境升级保留旧身份与操作历史，停用旧三账号的新增登录。每家服务商统一为一个 PROVIDER_BUSINESS 账号，拥有本公司配置、资料与应收相关动作，授权范围仅包含本公司。首次生成不再提供公共 acc-jd-config；已有来源启动时停用该账号，并升级各服务商账号，业务库将未完成配置事项交给对应公司。

模拟的对象包括原安装管理系统、订单权益系统、各服务商资料及应收系统、京东账单系统、计费依据系统、身份权限系统。接口可由同一个本地模拟服务进程承载，但记录归属、读取、写入、版本和失败行为分别维护。

```text
身份权限模拟接口 ──────────────┐
工单、方案、正式明细模拟接口 ────┤
购买订单与权益模拟接口 ─────────┤
服务商资料及格式模拟接口 ───────┤
原文件读取模拟接口 ─────────────┼→ 本系统后端 → 本系统 API → 工作台
京东账单模拟接口 ───────────────┤      │
服务商应收模拟接口 ─────────────┤      ├→ 实际转换、计算、保存、状态流转
计费条款与批准记录模拟接口 ─────┘      └→ OpenCode + Skill → 校验并保存分析
                                      │
人员确认 → 本系统后端 → 对应外部写接口 → 保存来源记录 → 外部接口重新读取核实
```

前端不调用模拟来源接口，不导入种子文件，不生成业务列表、金额、AI判断或成功结果。本系统后端也不能绕过外部接口直接读取模拟来源数据库。生成工具只为各模拟系统准备原记录和文件，本系统的事项、分析、人工决定和处理记录由实际流程产生。

配置转换、金额计算、权限检查、保存和操作接续必须实际执行。验证Skill时使用已实现的本地OpenCode，模型固定为DeepSeek V4.1 Flash（deepseek/deepseek-flash）；前端和模拟业务接口均不预置其判断结论。

## 2. 各外部接口提供的数据

### 2.1. 外部系统及数据归属

| 模拟外部系统 | 自身保存的数据 | 本系统用途 |
| --- | --- | --- |
| 身份与权限系统 | 测试账号、京东/服务商角色、动作权限、服务商及工单范围、账号有效性 | 取得可信身份与当前范围；后台执行身份与人员身份分开 |
| 原安装管理系统 | 工单、关联订单编号、方案、正式安装明细、材料索引、审核及补充动作 | 展示工单，整理资料，核查，提交正式明细、审核与补充 |
| 订单及安装权益系统 | 订单、安装权益、服务范围、上限、有效性和适用依据 | 核实安装范围，权益数量不当作实际安装量 |
| 服务商资料系统 | 各服务商原字段记录、模板说明、格式版本 | Skill生成转换规则，启用后程序处理后续资料 |
| 文件服务 | PDF、图片、XLSX的实际文件、所属工单、来源及版本 | 实际解析与原文定位，核实页面及表格是否完整 |
| 京东账单系统 | 京东原账单、原分项、工单分配、金额及版本 | 与服务商应收对照 |
| 服务商应收系统 | 各服务商应收、原分项、修订说明与版本 | 对账及取得服务商实际修订后的数据 |
| 计费依据系统 | 条款、适用与生效范围、费用批准记录、关联材料 | 核实费用依据，区分查无记录与未查全 |

来源变化接口用于让后台发现各来源新增或修订的记录，再分别调用对应详情接口取数。变化通知不携带预制的页面状态或AI结论，不能代替工单、资料、账单等各自的读取接口。

### 2.2. 跨接口必须一致的关系

| 关联 | 必须满足的规则 |
| --- | --- |
| 服务商—账号—业务记录 | 同一来源服务商编号保持稳定；权限覆盖与工单、原资料、应收归属一致，不按名称猜归属 |
| 工单—购买订单—权益 | 工单返回订单编号；权益接口核实该订单与该工单的关系，分别保留版本与适用范围 |
| 工单—方案—正式明细 | 三者指向同一工单；方案量、实际量分别保存，正式明细未提交是正常阶段 |
| 工单—材料—文件 | 材料索引中来源、文件编号、版本可以实际请求文件；正常文件字节与原记录相符 |
| 原资料—模板说明 | 原资料的格式编号及版本对应同一份格式说明；不明或不符时保留缺项 |
| 京东账单—服务商应收 | 以工单、服务商、账期、币种及明确范围核对；两侧编号、名称和分项结构可以不同 |
| 费用—条款—批准 | 条款与批准必须能核实覆盖哪些工单/费用及时间，签字材料不自动成为费用批准 |
| 退回—回复—新材料 | 回复引用确切退回动作及工单，新附件引用实际文件版本；后续分析仍接续原事项 |

场景数据先有统一的业务事实，再分别生成各系统自己的记录。只有内部生成和验收工具可查看完整事实与预期结果；运行时每个接口只返回其职责内的原记录。

## 3. 原始数据与文件准备

### 3.1. 规模与实际差异

| 数据集 | 要求 | 验收用途 |
| --- | --- | --- |
| 快速检查集 | 固定少量服务商、工单及明确场景 | 单接口排错，不代替常规集 |
| 常规联调集 | 严格10家服务商、100张工单、3个账期；每家有业务记录，工单数量有差异 | 多服务商列表、分页、统计、权限与业务处理 |
| 扩展集 | 独立测试配置可增加规模，不作为默认启动来源 | 后续规模验证，不预先承诺性能结果 |

默认来源固定为 demo-10-v2，十家服务商各有一份真实 Excel 安装明细样表，采用三套不同中文表头。九家字段说明完整，一家明确缺少数量含义说明。PDF、图片及复杂结构仍由独立测试验证，不扩大默认服务商数量。

正常文件采用真实PDF/PNG/JPEG/XLSX字节，文本及表格与来源记录一致。图片描述与原文识别结果分开；多页或多sheet材料须有可核实的完整范围。失败场景使用真实损坏文件、受控读取失败或实际缺页，不仅改变一个状态标签。

### 3.2. 生成配置与覆盖分配

每份数据集保存datasetId、生成器版本、固定种子、初始业务时间、服务商/工单/账期数量，以及各场景的确切数量。以确切数量分配场景，不同时使用两套含义不明的异常比例。相同版本、配置与种子得到相同初始业务记录和文件。

工单以一个“初始主场景”计数，每张只计一次；正式业务中后续可进入其他阶段。标准配置如下，九项合计100张，不把这些名称或预期结果作为接口业务字段返回：

| 初始主场景 | 工单数 | 模拟来源实际准备的事实 |
| --- | --- | --- |
| 待整理安装资料 | 20 | 有原始施工记录、方案与权益，正式明细尚未提交 |
| 安装证据一致 | 15 | 同段方案、正式明细与施工记录相互支持 |
| 安装数量差异 | 10 | 方案与正式明细有明确差异，原因和变更依据分别提供或缺失 |
| 安装材料不足 | 5 | 必需材料或内容实际缺失；不能只用未提交明细代表缺项 |
| 双方账目可核对一致 | 10 | 两侧范围及分项可对应，金额一致，必要依据齐全 |
| 双方账目存在差异 | 30 | 29 张数量或单价不同且算术正确，另 1 张明确总额异常；两侧原记录独立保留 |
| 对账依据未取得完整 | 4 | 账单、范围、适用条款或批准查询明确未取得完整 |
| 履约协调 | 3 | 工单具有需协调的履约事实，本系统按已有业务规则建立事项 |
| 工单只读查看 | 3 | 工单和授权关系可读，暂不产生需要办理的新问题 |

服务商格式接入按每家一份计算，共十份真实 Excel 样表，不与工单数相加。完整说明九份、数量含义未知一份；原始数据、字段说明和 Excel 字节由共享定义生成。正常配置可生成五个必要字段的映射并通过真实试转换，负例须显示具体缺项。

每个工单主场景至少有一个实际对象。账单覆盖三个账期，默认账单均为单工单范围；多工单分摊由独立测试覆盖。程序逐项核对一致时跳过模型；正常差额须能解释数量或单价差异及依据，不能只改单行金额造成乘积校验失败。不预置 AI 结论。

权限、版本变化、回复、超时等作为后续操作场景，指向现有来源对象，不重复计入初始工单总数。配置先校验总数、场景可适用性与最低覆盖，再使用固定种子分配具体对象；条件无法满足则拒绝生成，不静默降低覆盖。扩展配置必须明确每项数量，不隐式按比例取整。

### 3.3. 生成校验与交付文件

生成工具先写各模拟系统自身的原记录和文件；正常启动的本系统数据库为空，通过外部接口导入。不得直接插入已完成事项、AI分析、人工决定或已启用配置来代替主流程。

| 交付文件 | 必须记录 |
| --- | --- |
| 数据清单 | 数据集、生成器版本、种子、初始时点，各系统对象数、来源编号及关联 |
| 文件清单 | 文件所属记录、来源、版本、类型、大小及内容摘要 |
| 场景覆盖表 | 场景名称、适用接口、来源对象编号、涉及服务商/格式/账期及实际数量 |
| 数据校验报告 | 关联、金额、字段状态、文件内容、时间与版本一致性；明确失败原因 |
| 独立验收预期 | 每个场景的输入及版本、操作、预期来源变化、预期本系统结果及禁止动作 |

金额使用精确十进制。按量收费在计价依据明确时复算数量与单价；固定收费允许数量/单价为空。原分项和原总额独立保留，不能用重算结果覆盖原值。正常记录应自洽；特意准备的总分不符等负例必须命中预期错误，其余未预期错误阻止使用该数据集。

文件生成器固定文档创建信息、内部编号和排序，记录实现及依赖版本，支持字节摘要复现。初始时点只决定初始数据；后续操作使用可推进的测试时间，写入时间、来源版本随动作变化。真实模型自然语言不要求逐字复现，按事实与证据验收。

## 4. 模拟接口的真实行为

### 4.1. 分别读取

后台根据可信身份及业务关联，取得工单、订单、材料、账单等来源编号，再分别请求对应接口。一个接口失败不能由另一个接口或前端补造该记录；已经取得的其他资料可以保留，失败或缺项明确展示。

只读查询返回该来源实际保存的记录。按契约过滤权限及版本；需要特定历史版本时返回该版或明确不可取得，不静默换成最新。原始文件接口返回实际字节，不能只给文件名或预填解析结果。

变化发现须覆盖首次已有记录和后续新增/修改。第一次查询没有变化后，新增记录必须可以被后续查询发现；重复发现同一变化不得重复创建业务事项。分页、继续读取及重启恢复的技术参数由来源变化契约统一规定。

### 4.2. 写入、回查与外部修订

| 操作 | 模拟外部系统必须真正发生的变化 | 后续验证 |
| --- | --- | --- |
| 正式明细提交 | 保存确认内容及提交结果，生成确切正式明细版本 | 原提交结果回查与工单上下文读取均能对应同一份内容 |
| 审核通过或退回 | 保存本次动作及问题，保留操作编号和工单关联 | 回查得到该动作结果；退回真正成功后本系统才开放服务商回复 |
| 补充回复 | 保存正文、原退回关联、确切附件版本及结果 | 回复成功后后台真实准备新分析，附件与文本均进入对应输入 |
| 服务商修订应收 | 在服务商模拟来源中保存新版本、原分项及修订说明 | 应收读取接口返回新版；京东账单保持原值，本系统重新核对 |
| 修改方案、材料或条款 | 在各自来源保存修订版，并产生可发现的变化 | 后台分别重读有关接口，旧分析不冒充当前结果 |

服务商改账、改材料等外部动作由开发用模拟外部系统入口执行，只修改其自身来源。工作台不增加代改京东账单、代服务商改账的接口。触发变更之后，本系统仍须通过对应外部读取接口取得新版，禁止测试工具直接写本系统比较结果或事项状态。

同操作编号同正文重复请求返回原结果，不重复写入；同编号改正文按契约拒绝。来源版本已变化时拒绝覆盖新版。请求超时后按原编号回查；“没有收到响应”不等于“没有写入”。

### 4.3. 失败如何验证

测试控制与业务响应分开。每次测试指定目标接口、来源对象/版本、触发操作、失败阶段、发生次数和恢复条件；命中过程记入内部测试日志，不把预期答案返回Skill。

| 失败条件 | 实际行为与验收重点 |
| --- | --- |
| 调用前不可用 | 接口按契约失败，来源不发生写入；前端显示真实错误 |
| 已写入但响应丢失 | 来源保存成功结果，首次请求丢失响应；回查可核实成功，同编号恢复不二次写入 |
| 明确拒绝或版本冲突 | 来源保留拒绝结果或返回冲突，本系统不显示提交成功 |
| 指定文件版本不可取得 | 文件接口返回版本不可取得；不换新文件填旧证据 |
| 来源成功、本系统接续失败 | 保留来源成功，恢复本系统保存与交接，不再次外发 |
| 权限撤销 | 新请求按最新权限拒绝；既有未决操作按已登记恢复规则处理 |

常规运行不随机报错。测试结束按登记条件解除故障；同样的场景操作应能再次复现同一种失败。

## 5. 业务场景与接口调用闭环

### 5.1. 五类业务场景

| 业务场景 | 后台分别调用的接口 | 真实处理和验收结果 |
| --- | --- | --- |
| 服务商格式接入 | 身份权限、服务商原资料与格式、必要原文件 | Skill生成完整TRANSFORMATION_CONFIG；程序实际试转换；人员确认启用；后续同格式新记录直接由程序转换，无需再次调用模型 |
| 安装资料整理 | 工单上下文、购买权益、服务商原资料、原文件 | 实际解析与整理；人员确认后调用明细提交；回查与工单读取证实正文已保存 |
| 安装核查与补充 | 工单方案/正式明细、原文件、相关费用依据；操作时调用核查/补充同步 | Skill给出支持/冲突/不足证据；核查人决定；服务商成功回复后继续原事项与新分析 |
| 业务对账 | 京东账单、服务商应收、计费条款与批准、必要原文件 | 程序比较、Skill解释、人员处理；外部应收修订后重读并比较，单靠金额相等不完成对账 |
| 多服务商协作与查询 | 身份权限及对应各业务接口 | 本系统按真实导入数据分页、统计和展示；服务商不能越权读取其他服务商的记录或文件 |

### 5.2. 必须区分的数据情形

| 情形 | 数据及预期结果 |
| --- | --- |
| 权益量、领料量、方案量、实际量不同 | 各自在相应接口/原文中保留，整理结果只采用有证据的实际量 |
| 正式明细未提交 | installationDetailStatus=NOT_SUBMITTED，为正常整理阶段；没有其他缺项时不因此判资料缺失 |
| 未提供格式说明 | formatStatus=NOT_PROVIDED、formatDefinition=null；保留待确认，不造说明 |
| 已有说明但字段含义未知 | formatStatus=PROVIDED、对应meaning=null；该字段不能直接启用转换 |
| 资料与格式版本关联不符 | 保留原字段及真实格式版本，按契约列FORMAT_ASSOCIATION，不套旧配置 |
| 当前材料不足与指定版本不存在 | 前者保留业务缺项，后者由材料接口按版本读取错误返回，不能混用同一失败结论 |
| 无费用批准记录与批准查询未查全 | 分别表示完整查询未返回记录、查询范围不足；后者不能解释为没有批准 |
| 固定收费、零金额、金额未知、负向调整 | 分别按来源保存，空值不改零，负值不丢弃；固定收费不强求数量和单价 |
| 总额一致但分项不一致 | 来源保留各自分项，本系统不能仅凭总额判核对一致 |
| 同工单多事项、无事项工单 | 均能从实际导入工单查看；可见事项统计与详情一致，不通过假待办补齐页面 |

### 5.3. 每个场景的通过判据

独立验收预期至少包含：场景名称、来源对象及初始版本、需要调用的外部接口、操作顺序、应改变/不得改变的来源记录、预期本系统结果、证据位置、回查方式。确定性转换与金额精确比较；AI按关键事实、原文支持、缺项保留和证据引用核对，不以整段文案相同为通过条件。

完整正常链路、明确缺项、来源读取失败、写入结果未知分别验收。已明确错误的数据应触发相应拒绝或待处理，不能为让测试通过而修成正常数据，也不能将返回HTTP200直接计为业务成功。

## 6. 运行、保存与恢复初始数据

### 6.1. 来源数据与本系统数据分开

每个开发验证环境绑定一份数据集，包含相互隔离的各模拟系统来源存储、本系统测试数据库、文件空间与任务运行空间。以环境标识关联这几部分，不要求给全部生产业务表新增数据集字段。

来源记录由模拟接口维护；本系统数据库由实际业务服务维护。浏览器刷新或服务重启不得重置任何一侧。来源写入结果、版本、变化记录及未决操作必须能继续回查，不能因重启重新返回初始成功样例。

### 6.2. 恢复初始状态

开发工具暂停该验证环境接收新任务并处理正在运行的任务，再建立一套新的、完整配对的验证环境：各模拟来源恢复到同份生成产物，本系统数据库从空库开始，后台通过外部接口重新导入。检查通过后切换测试入口；旧任务及其迟到结果只属于旧环境，不能写入新环境。

不在共享业务库中按模糊条件逐表删除，也不让半份旧状态与半份新来源共同对外服务。恢复中断时保留原环境，新的未完成环境不可启用。验收同时核对来源初始摘要、本系统重新导入数量、任务归属与旧结果隔离。

### 6.3. 实际服务商文件与开发入口

实际文件通过现有上传API进入本系统，保留实际来源与工单关联，不补造配套京东账单或批准材料。含实际上传资料的验证环境不执行清空恢复；需重新开始模拟联调时另建环境，原环境及其文件、关联和处理记录完整保留。

生成、校验、模拟外部系统修订、故障启用、环境重启/恢复由开发工具或测试入口执行。业务人员仍只使用工作台已有页面，不承担造数和维护测试环境的操作。

## 7. 验收标准

| 编号 | 必须验证的结果 | 必备证据 |
| --- | --- | --- |
| 1 | 工单、权益、资料、文件、双方账单、费用依据分别调用相应外部接口取得；前后端均未旁路读取种子 | 各接口请求及返回、后台调用链、前端数据路径检查 |
| 2 | 常规集严格10家服务商、100张工单、3账期和§3.2覆盖；每家有真实 Excel 样表 | 来源对象计数、场景覆盖表、文件与字段内容对照 |
| 3 | 多个接口指向同一业务时编号、范围、版本及文件相符 | 跨接口关联校验、来源文件摘要与读取字节比对 |
| 4 | 初始生成可复现，意外错误阻止使用，预设负例命中预期处理 | 两次生成摘要、校验报告及负例结果 |
| 5 | 生成可执行转换规则，经实际试转换和确认后处理后续新资料；未知字段与格式变更不误套配置 | Skill产物、规则执行记录、启用记录、新资料转换结果 |
| 6 | 整理、提交、核查、退回、补充、对账均有真实来源读写及重新读取闭环 | 操作前后来源接口、系统保存、当前页面与原文证据 |
| 7 | 同编号不重复写入；冲突、丢失响应、结果未知及本地接续失败可按原操作恢复 | 来源实际写入次数、原编号回查、状态和责任变化记录 |
| 8 | 新增及修订可被发现并分别重读对应接口；重复变化不重复创建事项 | 来源变化记录、读取调用、版本与原事项接续记录 |
| 9 | 列表、统计、详情、材料及金额遵守各自权限；缺数据与无权限不填假值 | 跨服务商反例、各层错误响应、摘要与详情一致性检查 |
| 10 | 重启保留状态；新环境恢复完整；旧任务不写入新环境；实际上传环境保留完整 | 重启和恢复前后对照、迟到任务记录、实际文件及关联检查 |
| 11 | AI mock与真实Skill报告分开；真实运行使用实际接口输入，失败无固定答案兜底 | 运行模式、输入/Skill/模型版本、原始结果与独立证据校验 |

数据生成、外部接口、本系统业务闭环分别给结论。已经通过且输入、Skill与运行程序均未变化的结果可沿用，报告注明版本；新增接口和联调链路需要新增验证，不能复用单独Skill测试宣称整套业务已通过。
