## 1. 接口基本信息

| 项 | 本项目约定 |
| --- | --- |
| 用途 | 按来源、材料编号和指定版本，取得完整原文件供预览及后续解析 |
| 业务提供方 | 原材料所属系统或授权文件服务，实际提供方及协议待核实 |
| 逻辑调用 | `read_source_material` |
| 拟定 mock 请求 | `GET /api/admin/mock/external/sources/{sourceSystem}/materials/{sourceMaterialId}?sourceVersion={sourceVersion}` |
| 鉴权 | 服务端验证调用身份、材料实际归属及当前访问范围；知道材料编号或曾经读过材料均不等于当前有权限 |
| 只读边界 | 不上传、修改或删除材料，不提交审核结果，也不批准费用 |

路径和响应为本项目后台适配的开发约定，当前尚未实现。调用方不传任意下载 URL；适配层按已配置来源取得原文，不向浏览器暴露原系统凭据。工作台面向浏览器的预览、下载接口在本系统接口阶段定义。

此接口按已保存的引用读取材料；文件名称不能替代材料编号，文件名相同也不能推定版本相同。真实模式不得以 mock 文件掩盖读取失败。

## 2. 请求参数与版本规则

| 参数 | 位置 / 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| sourceSystem | path / 非空 string | 是 | 原材料所属系统；须是服务端已配置的来源，不能当作任意域名 |
| sourceMaterialId | path / 非空 string | 是 | 该来源内唯一的材料编号 |
| sourceVersion | query / 非空 string | 是 | 本次要求读取的确切版本；按字符串判等，不允许省略后默认读取最新版本 |
| 访问上下文 | 服务端调用上下文 | 是 | 已验证的身份与业务访问范围，不接受调用方自行声明权限 |

从工单材料索引取得前三项。索引中的 `sourceVersion=null` 时先处理版本缺失，不编造版本号调用本接口。其他业务资料也须由其所属系统提供可核实的材料引用；接入配置资料无需伪装成安装工单附件。

```text
GET /api/admin/mock/external/sources/installation_management/materials/material-image-001?sourceVersion=image-1
```

- 返回的来源、材料编号、版本必须与请求一致。不能在旧版本引用下返回最新文件。
- 提供方支持历史版本时，按当前权限取得指定版本；只提供当前版本时，仅当其版本与请求一致才可成功。
- 提供方已删除旧版本、只保留新版本或无法满足指定版本时，返回版本不可取得；若无法验证文件内容属于哪个版本，返回版本不可核实。
- 版本与文件内容的关联须由来源能力验证，不能仅凭文件名、读取时间或自行填写版本号证明。不能把一次读取前后的元数据查询当成来源已经支持原子读取。
- 读取旧版本供回看，不表示旧分析仍适用于当前业务记录。发现版本变化后，由后续处理流程重新取上下文、分析并更新原事项，人员不必重新创建事项或填写 Skill 指令。

## 3. 返回结构

### 3.1 字段

成功为 HTTP 200，外层统一 `code=0`、`msg="success"`、`data`、`requestId`；失败保留相同包装，`data=null`。下表为 `data` 内全部必返字段，只有 `sourceUpdatedAt` 可空。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| sourceSystem | 非空 string | 必须与请求一致 |
| sourceMaterialId | 非空 string | 必须与请求一致 |
| sourceVersion | 非空 string | 本次正文经核实的版本，必须与请求一致 |
| name | 非空 string | 该版本的文件名，用于展示，不作为文件身份 |
| mediaType | 非空 string | 实际文件类型；不能仅凭扩展名认定 |
| sourceUpdatedAt | string / null | 原系统提供的带时区更新时间；未提供则 null，不以取数时间替代 |
| retrievedAt | string | 本次取得完整内容的时间，带时区 |
| byteLength | 正整数 | Base64 解码后的原文件字节数，由实际完整内容计算 |
| contentSha256 | string | 完整原文件字节的 SHA-256，64 位小写十六进制；不等于原系统业务版本 |
| contentBase64 | 非空 string | 完整原文件字节的 Base64 编码，无 data URL 前缀；不返回文件片段、文件名或 AI 摘要作为正文 |

本次采用完整字节的 JSON 返回，便于 mock 与后台解析使用同一结构。接入真实来源时可从其下载或文件流协议读取，再转换为本契约；具体方式待提供方确认。缓存如被采用，须以来源、材料编号、版本共同区分，并在使用缓存前重新校验当前访问权限。

### 3.2 内容完整性与解析边界

- 本期开发支持 PDF、PNG、JPEG、XLSX，分别使用 `application/pdf`、`image/png`、`image/jpeg`、`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`。
- 只在完整读取、文件类型核实、版本对应一致后返回成功。读取中断不能返回已取得的片段；零字节不当作有效材料。
- 调用方对解码后的字节数和摘要复核，不一致时拒绝消费并记为读取异常。摘要用于发现传输或缓存内容不一致，不能独立证明材料真实或业务已批准。
- 文件完整读取后仍可能需要 OCR、表格解析或密码处理。这些属于后续解析能力；本接口不返回“识别完成”“证据充分”或审核建议，不把无法解析解释为无内容。
- 解析结果及证据位置必须继续关联该材料的来源、编号与版本。页码、表格位置及内容片段由后续解析产生，文件读取时不编造。

开发初始上限为解码后 2 MiB（2 × 1024 × 1024 字节），与当前原型附件边界相衔接；此限制是开发配置，尚未据真实文件量级验证，不作为生产容量承诺。超限返回明确错误，不能截断后交给 AI。生产容量须在真实材料核实后定稿，并与读取实现、超时和预览能力同次调整。

## 4. 失败与兜底

| 情况 | HTTP / code | 本系统处理 |
| --- | --- | --- |
| 必填参数缺失、来源未配置或参数格式非法 | 400 / 40001 | 修正调用参数，不自动改用其他来源或版本 |
| 身份未验证 / 当前无材料访问权限 | 401 / 40101、403 / 40301 | 停止读取，不能用缓存或另一服务商身份绕过 |
| 材料不存在或已删除 | 404 / 40401 | 提示材料不可取得，保留已有证据引用和历史记录，不伪装成空文件 |
| 材料存在，但要求版本不可取得 | 409 / 40901 | 提示所引用版本不可取得；按后续流程刷新上下文，不在旧结果中替换为新文件 |
| 无法核实正文属于要求版本 | 409 / 40902 | 停止将该正文用于判断，记录待核实的问题，不生成虚构版本 |
| 文件超过开发配置上限 | 413 / 41301 | 显示文件超限，保留事项待处理；不截断、不循环重试 |
| 文件类型不支持 | 415 / 41501 | 显示当前不支持该格式，不以更改扩展名绕过 |
| 来源读取不可用 / 超时 | 503 / 50301、504 / 50401 | 明示读取失败；临时错误可限次重试，仍失败保留重试入口 |
| 来源返回身份不符、结构非法、零字节、类型声明与内容不符或文件读取不完整 | 502 / 50201 | 拒绝正文，不以部分内容生成分析，记录调用标识 |

权限与版本判断必须先于正文对调用方可见。对于无法验证身份或范围的请求，不在错误信息中附带文件正文、凭据或其他业务方资料。

```json
{"code":40901,"msg":"所引用的材料版本已无法取得，请刷新资料后重试","data":null,"requestId":"mock-material-002"}
```

开发默认：单次完整读取最多等待 10 秒，仅遇 50301、50401 时在 1 秒后重试 1 次，含重试窗口最多 21 秒。同一次重试保留原来源、材料编号和版本。该配置尚未做运行验证，不是提供方 SLA；用户主动重试前仍须核验权限和当前引用。

单份材料失败时，保留其他已取得材料及原处理意见，暂停依赖失败材料的判断。不能把“没有读到批准材料”直接写成“该费用未获批准”。批量材料读取由上层编排，本接口仅处理一份指定版本文件。

## 5. 依赖方与后续验证

| 依赖方 | 使用方式 |
| --- | --- |
| 原文预览与下载 | 在当前权限下展示引用版本，保留原页面填写内容；预览或下载入口由本系统接口实现 |
| 安装资料整理及核查 | 后台取材料并交后续解析，形成可追溯的分析，不要求人员先逐份手动下载 |
| 费用依据核实及接入配置 | 读取各自授权的条款、批准记录或格式资料；是否支持源系统业务记录导出为文件须另行核实 |

角色走查：核查人员仍从分析结果进入“查看原文”；服务商仍按原事项补充材料。系统读取不增加人工启动 Skill、重新建事项或重复审核步骤。上传补充材料属于后续写入接口，不能用本只读接口代替。

后续 mock 覆盖：正确版本完整读取、旧版本可读、旧版本不可得、正文版本无法核实、权限撤销、相同编号不同来源、读取中断、超限、不支持格式、零字节、字节数或摘要不一致，以及读取成功但解析失败的衔接。真实对接须核实实际文件大小、格式、权限、版本能力及脱敏响应。

本轮只定义文档契约；mock、真实材料服务、解析与前端预览接口均未实现或联调。
