## 1. 范围与判据

本轮核对业务需求是否有完整人员路径、交接与结束条件是否一致，以及流程能否由已有 ER 和开发契约继续细化。核对对象为业务主流程及五份详细流程，共六份说明、十二张图。

| 安装核查与补充 | 2 | 9 | 8 |

| 配置确认 | 1 | 6 | 6 |
| 履约协同与共用异常 | 2 | 10 | 10 |

节点与关系按图中出现次数计数，包含主流程和详细流程的重复展示，不能当作状态枚举数、独立业务动作数或实际点击数。

通过条件：BRD 范围均有对应路径；六类职责可从入口走到明确结果；普通补充、异常、失败与变化有返回位置；技术恢复不增加人工审批；图文与责任归属一致。真实接口调用、AI 效果及操作效率不属于本轮完成证据。

## 2. BRD 范围覆盖

| 需求 | 对应流程位置 | 核对结论 |
| --- | --- | --- |
| 打开工作台直接处理分析结果 | 主流程 §1、各详细流程 §1—2 | 四类 Skill 提前准备结果与依据，日常办理不要求选 Skill 或写指令；准备失败须明确展示 |
| 接入配置 Skill | 配置确认 §2—5 | 核实含义、范围及当前候选试转换，一次确认启用；条件相同的后续资料复用 |
| 安装资料整理 Skill | 安装资料提交 §2—5 | 提前准备完整草稿与依据，人员更正缺项后提交；原 AI 输出与人工更正分别保留 |
| 安装资料核查 Skill | 安装核查补充 §2—5 | 差异与原文集中呈现，原核查责任人决定；材料相关不等于审核通过 |
| 对账差异解释 Skill | 业务对账 §2—5 | 程序计算、AI 解释、人员核实分别承担；双方原账保持独立 |
| 补充后的连续办理 | 安装核查补充 §3—4；业务对账 §4—5 | 问题、回复与更新结果接续原事项；成功补充后不再要求人员启动分析 |
| 工单查询、原文与处理追溯 | 主流程 §1、§5；原型页面清单 §1 | 授权查询、查看当前与历史依据、返回事项；查看不产生新决定，历史不被当前结果覆盖 |
| 原系统已有业务接续 | 安装资料提交 §1、§5；安装核查补充 §1、§5 | 取得已有正式记录后按当前阶段继续，不为接入新工作台强制重交；未知历史不补造 |
| 履约协同与异常处理 | 履约协同与共用异常 §1—5 | 按具体阻碍和原责任办理，结果明确后结束；普通补充不强制转异常 |
| 保持系统归属与本期边界 | 主流程 §3—5；业务对账 §1、§4；外部依赖清单 §2—3 | 服务商在原系统维护应收；未增加自动费用批准、改京东账单、付款、设备控制或完整订单库存管理 |

## 3. 六类角色完整路径与必要性

下表计数为一次成功路径的业务决定数；阅读、输入、查看原文和确认弹窗不单独计为决定。原系统同起点、同终点的实际点击数及耗时尚未测量。

| 角色 | 从入口到结果的路径 | 保留的业务决定 | 系统承担的准备与接续 |
| --- | --- | --- | --- |
| 服务商资料人员 | 打开草稿 → 核实完整事实 → 提交 → 查看结果；退回后在原问题下补充 | 初次提交一次；每个有效退回轮次成功补充一次 | 归集资料、提供草稿；提交成功后衔接核查，补充成功后自动准备分析 |
| 京东安装资料核查人员 | 打开结果 → 核实差异及原文 → 通过、提出补充或处理异常 → 查看实际结果 | 直接通过一次；一轮补充后通过共两次核查决定 | 提前定位差异、证据和回复；保留原事项，不增加 AI 审批 |
| 京东业务对账人员 | 查看比较与依据 → 处理真实疑点 → 查看回复或新版 → 核实剩余问题 | 无疑点不增批准；有疑点才发起问题或记录需人工判断的事实 | 对应项目、计算差额、取得新版并检查全部结束条件 |
| 服务商应收负责人 | 查看具体费用问题 → 核实本方事实 → 回复依据或在原系统修订 → 查看接续 | 回复路径一次；原账修订路径一次原系统修订决定 | 取得可靠新版后自动重比，不再强制回复“已修改”或重复上传 |
| 服务商对接人员 | 查看建议 → 核实含义与范围 → 核实当前试转换 → 启用 → 后续复用 | 每次有效配置启用一次；适用的后续资料无逐单配置决定 | 准备建议与试转换，变化后只重新处理受影响部分 |
| 京东物流履约协同人员 | 查看具体阻碍 → 按职责协调 → 未解决保存进展，已解决记录结果 | 实际解决本次阻碍后一次完成决定 | 提供原问题和已有进展；不增加 AI 确认、资料审核或费用审批 |

缺项、争议和多轮补充仍会产生必要的业务工作。不能将直接成功路径的决定数推广为全部业务固定操作数。新工作台减少准备工作的方向有流程依据，实际改善须在试运行中按 BRD §2.3 验证。

必要性走查：每个图中动作均能对应业务人员；读取、解析、计算、分析、结果核实和通知恢复由系统承担。安装事实在提交时确认，证据在核查时判断，费用疑点在对账时处理，字段含义在启用配置前核实；没有集中增加一层统一审核。

## 4. 跨流程一致性

| 检查点 | 统一约束 | 适用位置 |
| --- | --- | --- |
| 办理责任 | 每个事项有当前具体责任人；未落实时待分配，查看权不等于办理权；转交不改历史操作者 | 主流程 §1、§5；共用异常 §1、§5 |
| 正常结果与异常结果 | 提交成功、审核通过、核对一致、配置启用、阻碍解决、异常处置及真实停止分别表述 | 主流程 §5；各详细流程结束条件 |
| 完成前提 | 人员点击确认、保存确认内容与实际动作成功分别记录；未知结果不能提前交接 | 安装资料提交 §4；安装核查补充 §4；配置确认 §4 |
| 当前版本与人工编辑 | 当前输入、分析、候选与确认相互匹配；新结果不覆盖未提交意见，更改内容不能沿用旧确认 | 各详细流程变化及恢复章节 |
| 未知与缺失 | 读取失败、查不全、无权限和明确无记录分别处理；未知不填零，资料不可读不等于业务已取消 | 资料提交 §3；核查补充 §1；对账 §3、§5；配置 §1、§3 |
| 安装补充与费用问答 | 安装一轮有效退回至多一份成功回复；费用问题可保留多次实际回复。两者均防止同一次提交重复保存 | 核查补充 §3；对账 §4；核查决定与补充同步契约 |
| 未结束与已结束事项 | 未结束接续原事项；影响已完成结论的新事实保留原结果并关联后续；重复变化不重复建单 | 核查补充 §5；对账 §5；配置 §5；共用异常 §5 |
| 异常后续匹配 | 同工单、同服务商、同类型不足以确认同一工作，还须核实原问题和所需动作 | 共用异常 §4；处理事项域后续存储要求 |
| 原业务真实停止 | 必须有可靠停止依据；保存实际原因，无须继续时不创建多余后续事项；记录消失不能当作停止 | 共用异常 §2、§4—5 |
| 原账与金额 | 双方独立读取；可靠新版才参与重比，解释合理不自动消除差额；金额相等不能替代全部条件 | 对账 §3—5 |
| 技术恢复 | 已成功的确认、回复、源端写入或启用不重复办理；只恢复失败部分 | 各详细流程结果与恢复章节 |
| 通用异常边界 | 不以本地关闭覆盖未知外部动作，不调用安装通过或补充接口伪造异常同步 | 核查补充 §2、§4；共用异常 §4—5 |

## 5. 外部契约与 ER 的承接

| 流程所需能力 | 现有开发契约 | 承接边界 |
| --- | --- | --- |
| 准备安装上下文与原文 | 工单上下文、原始材料、购买订单与安装权益、服务商资料与格式说明读取 | 四类只读能力；方案、实际施工及权益含义分开，不从不完整数据推断可批准 |
| 正式资料提交与核查补充 | 正式安装明细提交；核查决定与补充记录同步 | 前者区分首次与允许修订；后者仅包含通过、退回、补充三类动作；成功、拒绝、处理中和结果未知分别反馈 |
| 业务对账 | 京东账单、服务商应收、计费条款与批准记录读取 | 三类只读能力；原账维护继续归原系统，不虚构工作台改账接口 |
| 自动接续、当前权限与分析 | 原记录变化发现；当前身份与业务权限取得；AI 推理与材料解析 | 稳定变化关联、当前授权及带依据分析；历史授权和旧分析不能批准新内容 |
| 本地协作与展示 | 后续本系统接口承担事项查询、草稿、费用问答、配置、进展、关闭及历史展示 | 当前外部清单未提供通用异常关闭写入；本地保存成功不表述为外部业务状态已同步 |

上表覆盖十二份逻辑开发契约。真实提供方、地址、来源完整性、版本证明、修订和重新审核条件、条件写入与结果回查仍待核实。契约齐备仅表示可以继续设计和开发 mock，不证明真实系统具备这些能力。

| ER 已表达的内容 | 表结构及后续接口必须保留的约束 |
| --- | --- |
| 处理事项、关联事项和完成原因 | 服务商与业务范围、配置可无工单、具体责任、正常与异常完成区分、同一原问题的后续关联和重复处理约束 |
| 原材料、固定输入、分析及人员更正 | 保存确切版本和引用位置；当前采用结果与历史结果分开；人工修改不伪装成 AI 原输出 |
| 人员确认与实际执行 | 固定确认内容与操作者；外部写入可关联原决定，未知结果可恢复；本地完成记录不能替代源端成功证据 |
| 安装退回、补充及费用问答 | 两类轮次条件分别保存，成功回复与执行尝试分开，历史问答不可覆盖 |
| 双方账单与固定比较 | 保存原分项、比较范围、对应关系、完整性及未决问题，不能只存两个总额 |
| 配置候选、试转换及生效版 | 保存各自输入与版本、适用范围和实际使用关系；启用只采用当前有效试转换 |
| 身份责任、变化与恢复记录 | 历史操作者保持；新动作按当前权限，已接收变化和成功动作不重复执行 |

这些是存储验收要求，尚未定义物理表、字段类型或 DDL；三十九类 ER 实体不直接等于三十九张表。

## 6. 原型差距与验证边界

原型 V1.1 已覆盖六类身份、主要处理页面、补充接续、试转换启用限制、保存进展和异常后续入口。以下差距须进入后续 PRD、原型修订和测试，不能以现有原型检查通过代替。

| 当前差距 | 后续应呈现或实现的行为 | 对应依据 |
| --- | --- | --- |
| 对账固定场景按两方总额相等模拟完成 | 分项、范围、版本、币种、税口径、总分及未决问题均满足要求才记核对一致；必要时提供记录已核实事实的交互 | 对账 §2—3 |
| 配置试转换由“查看试转换结果”按钮触发固定计算 | 系统自动准备匹配候选的结果；人员查看与核实，真实输入覆盖必要规则，修改后保留历史并重新准备 | 配置 §2—3 |
| 异常按工单、服务商、类型简化寻找后续，关闭后总会保留后续工作 | 按原问题和所需动作准确接续；真实停止且无须继续时记录依据和停止原因 | 共用异常 §4、§7 |
| 整理表单只覆盖固定项目和选项 | 核实完整项目列表、单位、供料方和工作范围，支持缺项、人工更正与新结果变化提示 | 资料提交 §2—3、§7 |
| 核查与协作以固定时序更新 | 展示真实提交进展、有效轮次、版本变化与恢复；完成后新事实形成关联后续 | 核查补充 §3—5 |
| 身份切换、保存、版本及失败均在浏览器模拟 | 按当前身份、具体责任与服务商范围控制；覆盖并发、撤权、结果未知和跨终端恢复 | 主流程 §1、§5；各契约 |
| 证据、模型及来源未真实接入 | 原文可核实、引用匹配实际版本；AI 只分析，程序计算，原责任人决定 | BRD §2—4；各详细流程 |
| 缺少新旧全程操作实测 | 同一角色和同类业务，从相同起点走到相同结果，记录点击、输入、等待、返修与总耗时 | BRD §2.3、§5 |

本轮核对的是文档覆盖、角色逻辑、图文及浏览器图形布局。未执行真实业务动作，未测量效率改善，也未证明所有最终交互已经存在于原型。

## 8. 阶段结论与下一步

**业务流程已完成全范围文档核对，可进入表结构设计。** 六类职责、四类 Skill、正常交接、补充、异常与变化后的接续均有设计依据；原型差距和真实接入待核实项继续保留。

本域已纳入 foundation 全范围核对；后续实现按本系统接口、系统流程及 PRD 接续。

当前不代表完整状态机、生产权限、外部同步、AI 效果或项目已实现。表结构之后继续按现有依赖推进本系统接口、系统流程、PRD、测试与开发。
