# 03-01-glossary 术语表

当前文档：[工作台 2.0 术语表 V1.11](glossary.md)，2026-09-20 已完成本轮口径核对。

业务概念在本项目里的统一叫法。PRD、原型、代码、数据库里的命名都以这里为准，避免同一个东西三种叫法。

## 文件命名

```
glossary.md        一个项目只维护一份
```

## 文件结构

| 列 | 说明 |
|----|------|
| 术语 | 业务上叫什么 |
| 定义 | 一句话说清它指什么，边界在哪 |
| 英文 / 代码命名 | 代码、表名、字段名里统一用什么 |
| 易混淆词 | 跟它容易混的词，说清区别 |

## 示例

```markdown
# 术语表

| 术语 | 定义 | 英文 / 代码命名 | 易混淆词 |
|------|------|----------------|---------|
| 任务 | 用户创建的一条待办，含标题、截止时间、状态 | task | 不是"提醒"——任务是要做的事，提醒是到点发出的通知动作 |
| 清单 | 任务的分组容器，用户按清单查看任务 | task_list | 不是"标签"——一个任务只属于一个清单，可以挂多个标签 |
| 完成 | 用户手动把任务标记为已做完 | complete | 不是"关闭"——关闭是管理员停用，任务是用户自己的 |

## 命名规则
1. 新增术语必须先登记到本表，再进 PRD 和代码。
2. 数据库表名、字段名一律用"英文 / 代码命名"列。
3. 一个概念只允许一个名字，旧名废弃时在表里标注"已废弃，改用 XX"。
```
