# 03-foundation 技术底座文档

开发动手前必须定稿的七类技术文档。它们是所有代码的统一口径：词怎么叫、外部接口怎么接、有哪些对象、业务怎么流转、表怎么建、接口怎么提供、请求在系统里怎么走。

> 当前状态（2026-09-20）：foundation 七类设计文档已完成并通过本地验收：术语表 V1.12、十二份外部契约、七域 ER、六类业务流程、七域 41 张业务与执行表及事务断言表、36 条本系统接口、五组十幅系统时序图。123 项本地 SQLite 检查通过；真实服务、D1、业务 Skill 与外部接入尚未实现或实测。 [全范围验收报告](coverage-review.md)。

## 目录与前置依赖

| 子目录 | 放什么 | 回答的问题 | 前置 |
|--------|--------|-----------|------|
| `03-01-glossary/` | 术语表 | 业务词在代码里统一叫什么 | BRD、原型 |
| `03-02-external-apis/` | 本系统依赖的外部接口文档 | 要调别人的哪些接口 | 术语表 |
| `03-03-er/` | 实体关系图 | 有哪些业务实体、实体之间什么关系 | 术语表 |
| `03-04-business-flows/` | 业务流程图 | 业务上谁先做什么、异常走哪条分支 | 术语表 |
| `03-05-schema/` | 数据库表结构 | 数据怎么存 | ER 图、外部接口（外部返回哪些字段要存） |
| `03-06-provided-apis/` | 本系统对外提供的接口文档 | 别人怎么调我们 | 表结构、业务流程图 |
| `03-07-system-flows/` | 系统流程图 | 请求在系统内部怎么走、失败在哪兜底 | 本系统接口、外部接口、表结构 |

**先定这七类文档，再写代码。** 按上表前置依赖推进，相关文档一致后定稿；下游文档的命名以术语表为准，冲突改术语表再同步下游。开发中改了任何一份，要同步改对应的代码和 PRD 引用。

## 三类图的两条边界

1. **业务流程图里不出现技术组件**（接口、表、队列）；系统流程图里不出现业务角色判断。
2. **图里的名字必须有出处**：实体名查 `03-01-glossary/` 术语表，接口和表名查 `03-05-schema/` 和 `03-06-provided-apis/`。

## 画图约定

**所有图统一用 `diagram-design` skill 生成**（入口：`.agent/skills/diagram-design/SKILL.md`），产出为单文件 HTML，与对应说明文档放在同一目录。每个图主题由两部分组成：

- `<主题>.md` — 文字结构（清单、关系说明、异常分支、兜底点），各子目录 README 有对应图种的章节要求
- `<主题>.html` — diagram-design 生成的图，md 中链接引用

**改图规则**：图改了要同步改引用它的表结构、接口文档和 PRD；图和文档不一致时，先核对最近确认的需求和变更记录，同次修正图文后再继续开发。
