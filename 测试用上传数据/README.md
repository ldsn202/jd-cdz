# 测试用上传数据与初始化案例

先按 [启动与运行指南](../启动与运行指南.md) 启动项目，打开 http://127.0.0.1:5174。首页展开“初始化演示案例”，点击对应事项即可进入，并切换到当前责任账号；也可通过右上角“切换账号”选择账号。

初始环境固定 **10 家服务商、100 张安装工单、154 个处理事项**。每家服务商一个账号；京东业务账号统一查看全部业务。所有分析均在具体事项详情手动触发。上传只保存并解析文件；要运行 Skill，仍需点击“运行分析”。

## 1. 四个 Skill 分别做什么

| Skill | 办理入口 | 输入 | 结果与人员动作 |
| --- | --- | --- | --- |
| provider-mapping-config | 服务商 → 映射配置 | Excel 样表、字段说明 | 原列与平台字段对照、实际转换值；试转换通过后由服务商确认启用 |
| install-detail-extractor | 服务商 → 安装资料整理 | 实际施工 Excel、PDF 或图片 | 实际安装明细草稿；服务商核对后正式提交 |
| install-evidence-finder | 京东 → 安装资料核查 | 方案、正式明细、施工记录、补充材料 | 一致或差异的依据；京东确认，或退回要求补充 |
| billing-diff-explainer | 京东 → 业务对账 | 双方费用差异、合同及批准记录 | 差异原因、涉及项目、建议核实内容；京东发起核实，服务商回复 |

对账金额和逐项明细均一致时由程序直接核对，不调用 AI。差异分析完成表示取得可处理的结论，仍保留真实差额，不能据此自动付款或把原账单改为一致。

## 3. 映射配置：上传 Excel 并看到真实结果

1. 切到对应服务商账号，进入“映射配置”中的本家公司事项。
2. 在“Excel 安装明细与映射材料”区域选择本目录文件，点击“上传 Excel”。上传成功后可下载原文件，并立即查看原表内容。
3. 点击该事项的“运行分析”。模型读取本次上传的列名、值与字段定义；未提供含义的字段会列为待确认问题。
4. 查看“候选规则与字段对照”和“字段映射结果”：前者显示原列怎样对应平台中文字段，后者显示实际转换值。
5. 试转换通过、待确认问题解决后，点击“确认启用配置”。之后同服务商、同格式的工单可使用这一版本。不同服务商的映射不会混用。

| 上传文件 | 上传账号 | 用法 |
| --- | --- | --- |
| `01-映射配置/SP-001-安装明细样表.xlsx` 至 `SP-010-安装明细样表.xlsx`（共 10 份） | 文件名对应的服务商 | 每家一份，包含桥架 12 米、电缆 45 米；各家列名不同，用来演示字段对应关系 |
| [SP-002-小数与零数量.xlsx](01-映射配置/SP-002-小数与零数量.xlsx) | SP-002 | 桥架为 17.25 米、电缆为 0 米；检验小数及零不会丢失或被改成默认值 |
| [SP-010-字段含义修正版.xlsx](01-映射配置/SP-010-字段含义修正版.xlsx) | SP-010 | 先运行初始来源资料，观察字段含义缺失；再上传本文件，以明确的标准业务列重新分析 |

SP-010 的初始来源字段说明缺少数量含义。两个 SP-010 Excel 的列名和值相同；“修正版”用于明确演示上传标准列后补全含义的步骤。只看列名相似不能擅自把未知业务含义认定为一致。

Excel 要求：`.xlsx`，首行为列名，每行一项明细，最大 10 MB。数量填数字，单位、供料方、服务范围独立列；不使用合并表头或公式。旧 `.xls` 请先另存为 `.xlsx`。可复制样表修改物料和数量，但应同时提供新字段的明确业务含义。

推荐先完成 SP-001 映射配置，再进入该安装事项运行。核对草稿中的实际数量、单位、供料方和服务范围，确认后提交。切换京东账号进入新产生的安装资料核查事项，手动运行，查看方案、正式明细和施工记录的对照，再确认通过或要求补充。

PDF / 图片先显示原文件和识别文字；可能提示“等待材料准备”。逐页阅读原文件，修正 OCR 文字，勾选已核对全部页并保存，再手动运行分析。这里的 PDF 与图片为可逐项阅读的文字施工记录。真实现场照片、签章或图形的业务含义不能仅靠文字确认替代，需要补充可核对的说明或记录；不应勾选不存在的确认事实。

京东可查看原材料、下载文件和阅读结果；服务商只能上传、提交自己公司的材料。

## 5. 退回补充：完整走一遍双方操作

使用 [SP-008-WO-2609-0046-补充施工记录.xlsx](03-退回补充/SP-008-WO-2609-0046-补充施工记录.xlsx)。

1. 京东进入 WO-2609-0046 的安装核查事项并运行。初始正式明细存在，但缺少施工记录。
2. 在核查操作中选择要求补充，写明需要本工单完整施工记录，提交退回要求。
3. 切到 SP-008 账号，在同一事项的“补充回复”区域上传本文件。文件明确列出电缆 15 米、入场搬运 1 次、基础施工 1 项、桥架 43 米，并分别说明供料方及服务范围。
4. 写明回复内容，点击刚上传文件旁的“将此材料版本附于回复”，再点击“提交补充回复”。仅上传文件不会代替提交回复。
5. 切回京东，在该事项再次点击“运行分析”。应能查看这次附件、回复历史和新的核查结论，再作出确认决定。

附件的实际文件会随回复进入模拟来源系统，可从双方材料视图重新读取；不能只看到一个附件编号。

## 6. 业务对账怎样演示

对账案例已经初始化双方账单、合同和批准记录，不需要额外上传文件。

- **SP-005 / WO-2609-0051**：金额与分项一致，程序直接核对。
- **SP-002 / WO-2609-0089**：搬运数量不一致，单价相同；分析应引用验收数量和合同，解释具体数量及差额。
- **SP-009 / WO-2609-0061**：基础施工单价不一致，数量相同；分析应引用 800 元合同单价，说明服务商 805 元的计费差异。

差异案例均可由京东发起核实，切到对应服务商账号回复。回复会保留在往来中；若原账单尚未修订，页面继续保留差额。没有依据的案例继续要求补充，不能为了演示“通过”而伪造批准。

## 7. 恢复初始状态与文件清单

需要重新演示时，在项目根目录执行：

```bash
npm --prefix code run restore
```

恢复最近保存的演示基线；恢复前系统会归档当前运行数据。随本次交付保存的基线是全部等待手动分析的干净状态。首次在另一台电脑启动，会生成同一版本来源并保存自己的初始基线，不依赖作者电脑路径。更换账号、普通重启不会清空上传及处理记录。

[文件清单.json](文件清单.json) 记录全部 **17 个上传文件**的账号、用途、工单和可核对的预期行值。这里只放演示材料，不含模型密钥；模型配置通过使用者本机 OpenCode 完成。
